# Baogao 日报任务设计

## 状态

用户已确认设计，待书面规格审阅。

## 目标

将 Nash AI 日报定时接口和任务标识改为 Baogao，并避免非会员查询超过前 1,000 条时因继续翻页而使整次任务失败。

## 范围

- 将 API 文件和路由迁移到 `src/pages/api/baogao/daily.api.ts` 与 `/api/baogao/daily`，移除旧 Nash AI 路由，不建立兼容别名。
- 同步更新 API 控制台任务标识、名称和路径，生产启动定时器清单，以及 `index.sh` 中的调用路径。
- 更新任务日志、邮件主题和日报标题中的产品名称为 Baogao。
- 保持现有日期范围、研报筛选条件、邮件接收人和发送流程。

## 抓取与截断处理

- 国内和国外搜索分别最多抓取 1,000 条。
- 根据接口返回的页大小计算请求页数，确保不会请求超出 1,000 条边界的页面；实际添加到结果中的记录也不得超过 1,000 条。
- 接口总量超过 1,000 条时，日报继续发送已取得的记录，并清楚标记对应分类已按非会员上限截断。
- 第一页失败或出现非会员上限以外的接口错误时，任务继续按失败处理，不发送不完整的成功日报。

## 验收标准

- 仓库内定时注册、控制台和脚本均只使用 `/api/baogao/daily`，旧 `/api/nash-ai/daily` 路由不再存在。
- 单类搜索结果不超过 1,000 条；总量高于上限时不会请求越界页，邮件会展示截断提示和实际结果数。
- 现有定时计划和手动立即执行能力继续可用。
- 检查所有旧路径/任务名称引用，并运行适用的静态检查；不调用外部 Baogao API 或发送验证邮件。

## 实施边界

本变更不增加本地研报文件落盘，不调整定时表达式、邮件接收人或第三方接口认证方式。
