# 定时日志清理设计

## 目标

腾讯云服务器存储空间仅 2GB。系统每两天在上海时间 03:00 执行一次清理，删除超过 2 天的运行日志及任务产生的历史文件，避免磁盘持续增长。

## 清理范围

1. 项目应用日志文件。
2. Reuters 日数据文件：`src/pages/data/reuters/*.json`。
3. 调度日志表：`scheduler_logs`。
4. 腾讯云/PM2 日志：通过部署侧 `logrotate` 配置处理；应用内清理器不直接操作外部进程日志目录。

股票、交易、配置及其他业务数据不参与清理。

## 保留规则

以文件修改时间、Reuters 文件日期及调度日志创建时间判断。每次运行删除严格早于当前时间减 2 天的数据；最近 2 天数据保留。删除失败记录错误并继续处理其他清理项，不因单项失败中断整个清理任务。

## 调度与执行

- Cron：`0 3 */2 * *`
- 时区：`Asia/Shanghai`
- 任务使用全局单例，避免开发热加载重复注册。
- 提供手动触发/状态查询接口，返回扫描数量、删除数量、失败数量及最近执行时间。
- 定时任务异常只记录错误，不影响主应用请求。

部署 PM2 时设置 `PM2_LOG_DIR` 指向实际日志目录，例如 `/home/app/.pm2/logs`；未设置时不扫描外部目录。

## 安全边界

- 删除前校验路径必须位于允许的日志目录内。
- 仅删除匹配的 Reuters JSON 文件及日志文件，不使用递归删除项目根目录。
- DB 清理使用带时间条件的 `DELETE`，不清空整表。
- 首次上线先 dry-run 统计候选项，再启用实际删除。

## 验证

- 单测：时间边界、目录白名单、文件筛选、DB 删除条件。
- 集成验证：构造超过 2 天及最近 2 天的文件/记录，确认只删除前者。
- 验证 cron 使用上海时区，每两天 03:00 触发。
- 检查清理失败时其他类别仍继续执行。
